kith-sessions — terminal `kith <agent>` sessions the host can list and continue on the phone (continue anywhere).

  kith-sessions record                     SessionStart hook (stdin: the hook's JSON): writes $KITH_STATE/live/terminal/<sid>.json
                                           for a listable session, nothing otherwise. Never fails the session.
  kith-sessions resolve AGENT THREAD PID   for `kith AGENT --resume THREAD`: prints shell assignments (r_sid, r_cwd, r_from); the host
                                           names the session (POST /api/resolveThread), else a raw Claude session id found on disk.
                                           Takes the session's writer claim for PID (the launcher's shell, which then execs `run`)
  kith-sessions claim SID PID [PERSON [AGENT]]  for a one-shot `claude -p --resume SID`: takes the writer claim for PID (the launcher's shell, which
                                           then execs claude), waiting up to KITH_CLAIM_WAIT s (default 5) while another writer holds it;
                                           then exits 1 with "held by <kind> (pid N)". resolve ... oneshot does the same for -c/-r.
                                           A fresh one-shot claims the --session-id bin/kith chose for it the same way.
  kith-sessions terminal SID PID [PERSON [AGENT]]  for an interactive run that resolve did not claim (a fresh one, on the
                                           --session-id bin/kith chose; KITH_RESUME): the claim, kind terminal, for PID (the
                                           launcher's shell, which then execs `run`, which gives it back); refused at once when held
  kith-sessions release SID                gives back SID's claim when its holder is the caller's parent (the launcher's shell, same start time),
                                           else exits 1 and touches nothing (`kith AGENT --held` after a resume: terminal.open takes the claim itself)
  kith-sessions proc PID PERSON AGENT     every non-owner run: a session-less `proc-PID.claim` naming the person, so the revoke sweep
                                           finds the run (and the claude below it) after a host restart
  kith-sessions sweep PERSON...            revoke or removal with no host running: ends the live holders of every claim naming one of
                                           these people (and their bots), and what those started; the owner's claims name no one
  kith-sessions pick AGENT                 for `kith AGENT -r`: the agent's recent sessions (cost ledger runs with a transcript),
                                           numbered on stderr; reads a number on stdin and prints that session id
  kith-sessions latest AGENT DIR           for `kith AGENT -c`: the id of the agent's newest session begun in DIR
                                           (both only name a session: `resolve` still claims and checks it)
  kith-sessions run AGENT -- CMD...        run CMD (claude) as a child: signals and exit code pass through; afterwards gives back the
                                           claims of this process and says how to get the session back: `kith AGENT --resume ID` (also when the host took it over)

Registry file (contract with the host, serve/): dir 0700, file 0600, written by tmp + rename:
  {"v":1,"sessionId","agent","cwd","transcriptPath","pid" (the claude process),"project","source","resumedFrom","startedAt",
   "account" (the login it was made under: KITH_ACCOUNT_ID, e.g. claude or claude:work; bin/kith resumes it only there)}
Writer claim (contract with the host, serve/host/src/terminal/claim.rs): $KITH_STATE/live/terminal/<sid>.claim, made whole in a
temp file and linked into place (exclusive), 0600: {"pid","procStart","at","kind"}. Whoever holds it is the one writer of the
session, before the registry file exists and with the host down. Stale (pid gone, or started at another time) = free, taken over by rename.
`--resume` claims BEFORE it asks whether the host is busy. A fresh run is claimed too, from before claude starts: bin/kith picks its
session id (--session-id) and claims that, so there is no moment between claude's start and its SessionStart hook in which the host
could take the session for a writer it does not see.
Live = the pid runs and ~/.claude/sessions/<pid>.json names the same sessionId (the host decides; resolve reuses it).
Listable = the owner's own run of one of these kinds (the file's "kind", with "label" saying who started a one-shot and
"procStart" the claude process' start, for the host's liveness when claude keeps no session file):
  terminal  interactive, started in a terminal by `kith <agent>`: the launcher sets KITH_TERMINAL_SESSION=1 for exactly that run
  ask | schedule | helper   a one-shot: bin/kith sets KITH_RUN_KIND for exactly that run from what its launcher passed
            (kith-ask, kith-sched: KITH_LAUNCH_KIND) or, started by another run of the owner's, `helper`.
Never listed: KITH_PERSON runs, the host's own runs (KITH_VIA=serve, channels, tidying), KITH_HIDE_SESSION, agent worktrees.
