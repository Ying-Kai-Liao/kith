kith-auth — which agent may use which shared service, and with which account.

  kith-auth ls                              every agent: the services it needs, its grant, whether the secrets resolve
  kith-auth grant <agent> <service> <profile>   let an agent use a service as that profile (e.g. notion/library);
                                          several agents as a,b,c, or --all for every agent whose needs list it;
                                          several profiles as p1,p2 (kith serve: one bot each, telegram/hq,telegram/x)
  kith-auth granted [--for AGENT] <service> the profiles granted, one per line
  kith-auth revoke <agent> <service> [--profile P]   with --profile, only that profile's grant goes
  kith-auth holders <service> [--json]      the agents of this Mac granted a profile of that service, one per line (--json:
                                          [{agent, profiles}]); read live from the grants, so a revoke drops an agent and an
                                          undo brings it back. The owner's runs see every holder; a guest's only the
                                          holders it may use itself (kith ask would refuse the rest)
  kith-auth set <profile> <VAR>             store a secret in the macOS Keychain (prompts; never echoed) and point
                                          the profile at it
  kith-auth set <profile> --stdin-json [--grant AGENT]   the host's route (a Key card): stdin is one JSON object
                                          {"VAR": "value", ...}; every VAR must be one the service declares in `secrets`
                                          (values non-empty, no NUL, at most 1536 bytes: the `security -i` line limit).
                                          Written to the Keychain through `security -i` fed on a pipe, so a value is never
                                          on any argv or env, nor in output, auth.json or auth.log. --grant also lets
                                          AGENT use the service as that profile, besides any grants it already has.
                                          Prints {"profile","service","vars","granted"}; on failure a fixed message only.
                                          Profiles are <service>/<account>, account ^[a-z0-9][a-z0-9._-]{0,39}$
                                          (github/work, github/personal): several accounts per service, granted per agent.
  kith-auth account-state <agent> <service> --json   read-only, no secret read: {declared, secrets, granted, missing,
                                          profiles:[{profile, account, owner, agents}]} (missing: the VARs the agent's first
                                          granted profile lacks, all of them when it has none)
  kith-auth keys --json                     read-only, never values: [{profile, service, account, owner, vars, agents,
                                          last_used}]; last_used is the latest hand-out in auth.log
  kith-auth connect <agent> <connector> [--profile P] [--json]   (kith <agent> connect) grant the agent a connector on this
                                          Mac: a host connector (a file in this Mac's services folder) as <id>/host, a profile
                                          marked {"store": "host"} (its secrets stay in the host); a service that needs keys takes
                                          --profile, or its one existing profile. Twice is fine. Reaches the owner's runs
  kith-auth disconnect <agent> <connector> [--json]   take it away again (nothing connected: ok, changed false)
  kith-auth connectors [available] [--json] what this Mac can connect: kernel MCP services and the host's connectors
  kith-auth connectors <agent> [--json]     what the agent has: name, source (kernel|mac|agent), kind, profile, and whether a run
                                          starts it (ok, missing secrets, signed out, no such profile, unknown service)
  kith-auth mcp-config <agent>              the --mcp-config JSON for an agent's granted MCP services (bin/kith uses it)
  kith-auth mcp-names <agent>               the same servers by name and real command only: reads auth.json, no secrets, no keychain,
                                          no browser profile (what kith <agent> --info-json lists)
  kith-auth helper-mcp <agent> ask|deny     PreToolUse hook of a kith:<agent> helper: a kith MCP service's tool the agent
                                          isn't granted for this run's person gets ask (owner's session) or deny (anyone
                                          else's); other tools pass
  kith-auth exec [--for AGENT] <service> -- CMD...   run CMD with that service's secrets in its environment only
  kith-auth exec [--for AGENT] --secret <id> [--as VAR] -- CMD...   run CMD with a secret a room member was handed once
                                          (rs_<hex>, from `once put`) in VAR (default KITH_SECRET), in its environment only;
                                          the owner's runs only, for the agent it was handed to, once: it is deleted first
  kith-auth once put <id> (--agent A | --bot B) --expires MS   a one-time secret (stdin: the value, <= 1536 bytes, no NUL)
                                          for one holder, in the Keychain item kith/once/<id>; auth.json keeps who, when it
                                          was made and when it lapses (MS since the epoch, at most an hour ahead), never the value
  kith-auth once copy <id> --from <profile> --var VAR (--agent A | --bot B) --expires MS   the same from a stored key,
                                          which never leaves kith-auth
  kith-auth once take <id> --bot B          prints the value once and deletes it first (the host's pipe: a bot's fetch)
  kith-auth once drop <id>                  deletes the item and its entry; nothing is wrong if it is already gone
  kith-auth once list --json                [{id, agent|bot, created, expires}]; never values (the host's sweep)
  kith-auth get  [--for AGENT] [--profile P] <service> <VAR>   print one secret, for an agent's own tool to call;
                                          --profile picks one of several granted profiles
  kith-auth env  <agent> <service> [VAR=value | VAR=]  this agent's own settings for a service (not secrets), e.g.
                                          kith-auth env personal jev-browser JEV_BROWSER_HEADED=1; VAR= drops one
  kith-auth browser <name> [<browser>]      a browser profile (its logins, in ~/.kith/browsers/<name>) and the browser
                                          that made it: chrome, chromium, msedge, firefox, or an app's path

People (who may use which agent, and how; the run's person is KITH_PERSON, unset = the owner):
  kith-auth people [ID ...] [--matrix|--json]   each person: their accounts, the profiles they own, every agent they can
                                          reach (own row, everyone row, helper) with its mode, and the account each
                                          service would really use in their runs; ID for one person in full (the
                                          owner's agents too); --matrix: agents × people at a glance; --json:
                                          [{id, name, owner, bot_of, provider, root, revoked (they or their bot's
                                          owner), revoked_at (their own), kith (account id or ''), handles, agents [{agent,
                                          role (the row's preset), via own|everyone}]}], each bot after its parent;
                                          bots are listed under their owner (kith people ls --json: the invitees)
  kith-auth person <id> [name=.. lang=.. tz=.. owner] [--rm]   a person; `owner` marks you (one owner); --rm forgets
                                          them (rows, grants and bots go; their memory stays to delete by hand) and
                                          retires the id: no new person or bot gets it, so nobody else ever reads
                                          their memory and files or uses their logins
  kith-auth person <id> --rm --unused      remove a person who never had anything (kith serve's undo of an invite that
                                          was never sent): the id is not retired; refused if they have anything
  kith-auth retired <id>                   exit 0 and why when a new person can't take the id (removed, an old id of
                                          someone, or memory, files or a profile an earlier removal left), else 1
  kith-auth person <id> --revoke | --unrevoke   revoke: they stay in kith, reach nothing (the `*` row included),
                                          their bots go dormant and kith serve tells them their access was removed;
                                          undo brings back every row as it was. On a Mac linked to the Kith cloud it
                                          goes through kith serve to every Mac of yours, and is refused while the cloud
                                          can't be reached (--local: this Mac's file only, what kith serve writes)
                                          Until the core is the authority, a revoke, an undo and a removal also reach
                                          the core's store (people.suspend / undo / removePerson) once auth.json is written; a core
                                          that can't be reached is said on stderr (no retry)
  kith-auth person <id> --clear-temp        removes their runs' Claude Code temp folder (<machine>/run/t/<id>);
                                          --rm and a revoke do it too, kith serve once it has stopped their runs
  kith-auth person <id> id=<new>            rename: memberships, grants, owned profiles and invites come along; the
                                          old id stays as an alias (chat threads they started stay theirs)
  kith-auth bot <id> --of <person> [name=.. provider=..] [--rm]   a cloud agent that joins as a guest of that person (a
                                          bot person: never more than its owner's access, checked live; its cost is
                                          on the owner's line); --rm removes it and its memberships
  kith-auth bots-cap <amount|off>           optional monthly cap on all the Mac owner's bots together (default off);
                                          other owners' bots spend from that owner's own budget= (--json: the cap
                                          and the owner's bot ids, for kith-cost bots)
  kith-auth handle <id> <platform> <user-id> | --rm   the person's account on a platform (numeric id, not a username)
  kith-auth invite <id> [minutes]           a CHANNEL /link code (not an app invite: that is kith invite add); one-time, default 15 minutes; they send /link CODE to kith serve's bot
  kith-auth link <platform> <user-id> <code>   bind that account to the code's person (kith serve's channels call it)
  kith-auth whois <platform> <user-id>      the person behind an account, or exit 1
  kith-auth who <platform> <user-id>        the same as JSON for kith serve's channels: {person, owner, was, owner_id,
                                          owner_linked, revoked, held}; person null when no one is linked; held: this
                                          Mac is linked to the Kith cloud but not in sync with it, so the channels wait
                                          before serving anyone but the owner
  kith-auth preset <name> [mode=.. deny=a,b] [--trusted] [--rm]   a named bundle of permissions memberships point at
  kith-auth member <agent>[,..] <id> [preset=.. mode=.. deny=.. model=.. helpers=a,b budget=USD env.VAR=..] [--trusted] [--rm]
                                          let a person use an agent, with their own settings on top of the agent's;
                                          <id> '*' is everyone kith knows (not unknown senders); their own row wins.
                                          mode=bypassPermissions or auto is a free shell on this Mac as you: refused unless
                                          --trusted (a row or preset without it runs in default mode).
                                          budget=20: at most $20 a calendar month of their runs of that agent
                                          (helpers they reach through it included; kith cost people shows it)
  kith-auth budgets <agent> --json          read-only: {person: dollars a month or null} for each person with a row
                                          of their own on the agent (the apps' Access > People)
  kith-auth access <agent> <id> read|write|domain <path|host> [--by <id>] [--rm]
                                          "always" on an escape card: a place or website a member's (or bot's) boxed runs of
                                          that agent may reach, beyond the box. Not for secrets or the paths a run may never
                                          write (rule W); not for the owner or someone with no row of their own; a bot gets
                                          no more than its owner holds. Listed as `access` in `resolve`. --rm takes one
                                          away as it is written, whatever has changed since. --by: the person who
                                          approved it (themselves, or their bot's owner), refused unless they are a
                                          member of the agent now; without it the owner did. A member made a guest
                                          loses the entries they approved.
  kith-auth agent-access <agent> [--json] | <agent> domain <host> [--rm]
                                          "always, for everyone" on an edge card: a website every guest of that agent (an
                                          invited person, a bot guest; never the owner) may reach, kept on the agent so it
                                          needs no row. With no host: lists them, the package's `guest_domains:` too. They
                                          join `access` in `resolve` and the ledger (person `*`). Owner's only; a person
                                          removed, or a bot, still gets no more than they are allowed to run with.
  kith-auth jobs <agent> [--person ID] [--domain HOST | --helper NAME | --door NAME[@DIGEST]] [--json]
                                          read-only: the jobs the agent's capabilities.yaml declares (domains, helpers,
                                          doors), for a person ticked or not and what a package update added since the
                                          tick (added, hash, declined); --domain/--helper/--door: only the job that holds it
  kith-auth door <agent> <id> <door@digest> [--json]
                                          read-only: may the person's runs of the agent start this door now (ok, or
                                          owner, revoked, not-allowed, held, stale, no-job, not-ticked, widened,
                                          declined, owner-lacks: a bot's tick has it, its owner doesn't); a door's
                                          start asks it under the auth lock (kith_door)
  kith-auth job <agent> <id> <job> [--shown JSON | --decline HASH | --rm]
                                          tick a job for a person's own row (never `*` or the owner): their runs of the
                                          agent get its pieces as they are now, or as --shown listed them, and never more
                                          when the package grows (`resolve` lists jobs, doors and the domains in access).
                                          --decline: the No of the card that offers what an update added
  kith-auth helper <agent> <id> <helper> [--once | --rm]
                                          "always" on a helper card: their runs of agent may call helper (the row's
                                          helpers). --once: one launch within five minutes, used up by `resolve --take-once`
  kith-auth ledger [--person ID] [--agent AGENT] [--json]   read-only: the grants ledger, every lasting grant for anyone
                                          but the owner: the access above (kind read|write|domain), ticked jobs (job),
                                          the helpers a row may call (helper) and a person's own
                                          service grants (<agent>@<person>, kind service, target the profile). --json:
                                          [{key, kind, agent, person, name, target, since, approved_by}] (since: ms or
                                          null; approved_by: owner, a person id, or null for an entry from before it
                                          was recorded and for service grants)
  kith-auth ledger --rm <key>               takes that one entry away, as listed; exit 1 when the ledger has no such key.
                                          key = <kind>:<agent>:<person>:<target> (kind, agent and person never hold a
                                          ':', so the target is all that follows the third)
  kith-auth owner <profile> <id>|-|default  the profile is that person's (their logins, their calendar); - = shared;
                                          default: logins and browser profiles are the owner's, keys and bots shared
  kith-auth share <profile> <id>[,..] [--rm]   it stays its owner's, and these people's runs may use it too (through
                                          the agents granted it that they may use)
  kith-auth may <id> <agent> [--via AGENT] [--once]   exit 0 if the person may use the agent (--via: called as AGENT's
                                          helper; --once: a `helper --once` not used yet counts)
  kith-auth resolve <agent> [--person ID] [--via AGENT] [--take-once]   the run's effective person settings, as JSON
                                          (bin/kith uses it); held as in `who` (the channels wait for the cloud sync
                                          before they serve). --take-once: a helper launch may use up a `helper --once`

Three layers, so sharing an agent never shares an account:
  kernel/services/<name>.json   what a service is: kind (mcp | cli | login), how to start it, which env vars it needs.
                                In the repo; no secrets.
  agents/<a>/capabilities.yaml  `needs: [service, ...]`: what the agent asks for. Part of the agent package.
  ~/.kith/secrets/auth.json      profiles (an account: where each secret comes from) and grants (agent → service →
                                profile). Yours alone, never in the repo. Holds references, not secret values.
                                Also env (agent → service → VAR: value): plain settings that override the
                                service's own env for that agent only.

People are tables in the same file, each fact in one place: people (who someone is, their handles), presets
(named permissions), members (agent → person → preset and overrides: access is the row existing) and grants keyed
`<agent>@<person>` for a person's own accounts, tried before the agent's. A profile with "person" is that person's:
a run for anyone else never gets it, whatever the grants say. The owner may use every agent with no membership.

Browser profiles: logins belong to a browser profile, not to a tool, so every browser tool an agent has (each
service with "browsers" in its json) opens the agent's one profile: `kith-auth grant <agent> browser browser/<name>`;
without a grant, the agent's own (browser/<agent>). Agents granted the same profile share its logins, though only
one run can have it open at a time. A service gets $KITH_BROWSER and $KITH_BROWSER_PROFILE for its env and args, and
is left out of a run when it can't drive the profile's browser (a profile is only ever opened by the browser that
made it).

Secret sources in a profile: "keychain:SERVICE#ACCOUNT", "env-file:PATH#VAR", "env:VAR". A `login` service (codex,
a Chrome profile) has no secrets here: the tool keeps its own login, and the grant only says who may use it.

The agent comes from KITH_AGENT (set by bin/kith) or --for (an agent's own tool naming its owner). This is least
privilege between cooperating agents. For the owner it is not a sandbox: an agent with a shell can still read files it can see.
Non-owner Claude runs (a person or a bot) are different: bin/kith starts them with the OS sandbox of Claude Code around Bash
(macOS seatbelt), so the credential folders and other people's files are closed to a shell too.
